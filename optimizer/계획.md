## 1. ADMM 기반 QP 솔버

### 1.1 개념

**Quadratic Programming (QP)** 은 다음과 같은 형태의 최적화 문제입니다:

$$
\min_x \; \tfrac{1}{2} x^\top P x + q^\top x \quad \text{s.t.} \quad l \le A x \le u
$$

여기서 $P \in \mathbb{R}^{n \times n}$ 은 대칭 양반정부호(symmetric PSD), $A \in \mathbb{R}^{m \times n}$ 입니다. 부등식·등식 제약을 모두 lower/upper bound 형태로 통일한 것이 OSQP 스타일의 표준 form 입니다 (등식 제약은 $l_i = u_i$).

**ADMM (Alternating Direction Method of Multipliers)** 은 큰 최적화 문제를 두 개의 변수로 분리한 뒤, 각 변수를 번갈아 업데이트하면서 푸는 일급 기법입니다. QP에 적용하면 다음과 같이 보조변수 $z$ 를 도입합니다:

$$
\min_{x, z} \; \tfrac{1}{2} x^\top P x + q^\top x \quad \text{s.t.} \quad A x = z, \quad l \le z \le u
$$

이렇게 분리하면 **(1) $x$ 업데이트는 단순한 선형방정식 풀이**, **(2) $z$ 업데이트는 box projection (clip)** 이라는 두 개의 쉬운 부분문제가 됩니다.

### 1.2 핵심 반복식

ADMM 의 한 반복은 다음 세 단계로 구성됩니다.

**(1) Primal x-update (KKT 시스템 풀이)**

$$
\begin{bmatrix} P + \sigma I & A^\top \\ A & -\rho^{-1} I \end{bmatrix}
\begin{bmatrix} \tilde x^{k+1} \\ \nu^{k+1} \end{bmatrix}
=
\begin{bmatrix} \sigma x^k - q \\ z^k - \rho^{-1} y^k \end{bmatrix}
$$

이 행렬을 **KKT matrix** $A_K$ 라 부르고, 이 시스템을 푸는 것이 한 반복에서 가장 비싼 부분입니다. 여기서 $\sigma > 0$, $\rho > 0$ 는 ADMM 페널티 파라미터, $y$ 는 듀얼 변수입니다.

핵심 관찰: $A_K$ 는 반복 중에 **거의 변하지 않습니다**. 따라서 LDL 분해를 한 번만 하고 forward/backward substitution 만 반복하면 됩니다. 논문에서 ADMM을 GPU 병렬화에 선택한 결정적인 이유입니다.

**(2) z-update (boxing projection)**

$$
z^{k+1} = \Pi_{[l, u]}(\alpha A \tilde x^{k+1} + (1-\alpha) z^k + \rho^{-1} y^k)
$$

$\Pi_{[l,u]}$ 는 단순한 element-wise clip 입니다. $\alpha$ 는 over-relaxation 파라미터로 보통 1.6 정도를 씁니다.

**(3) Dual y-update**

$$
y^{k+1} = y^k + \rho \big( \alpha A \tilde x^{k+1} + (1-\alpha) z^k - z^{k+1} \big)
$$

**(4) 수렴 판정**

primal residual 과 dual residual 이 모두 작아지면 종료:

$$
r_p = A x - z, \qquad r_d = P x + q + A^\top y
$$

$\|r_p\|_\infty < \epsilon_{\text{abs}} + \epsilon_{\text{rel}} \cdot \max(\|Ax\|_\infty, \|z\|_\infty)$ 와 같은 mixed tolerance 를 쓰는 것이 일반적입니다.

### 1.3 알고리즘 요약

```
입력: P, q, A, l, u, σ, ρ, α, ε
1. KKT 행렬 구성
2. LDL 분해 (한 번만)
3. x, z, y 초기화 (보통 0)
4. 반복:
     (a) RHS 갱신 후 LDL backsolve → x̃, ν
     (b) z 갱신 = clip(α A x̃ + (1-α) z + y/ρ, l, u)
     (c) y 갱신
     (d) residual 계산 → 수렴 시 종료
5. return x, y
```

### 1.4 Python 구현 가이드

#### Step 1: 등식 제약만 있는 KKT 시스템 직접 풀기 (반나절)

ADMM 으로 바로 가지 말고, KKT 시스템 자체에 친숙해지는 게 먼저입니다.

```python
import numpy as np
import scipy.linalg as la

# min 0.5 x^T P x + q^T x  s.t.  A x = b
def solve_eq_qp(P, q, A, b):
    n, m = P.shape[0], A.shape[0]
    KKT = np.block([[P,         A.T],
                    [A,         np.zeros((m, m))]])
    rhs = np.concatenate([-q, b])
    sol = la.solve(KKT, rhs)
    return sol[:n], sol[n:]   # x, ν
```

이걸로 손으로 풀 수 있는 2D 문제 ($\min x_1^2 + x_2^2$ s.t. $x_1 + x_2 = 1$, 답은 $(0.5, 0.5)$) 부터 검증하세요.

#### Step 3: 수렴 판정과 디버깅 출력

매 N iteration 마다 `(iter, ‖r_p‖, ‖r_d‖, obj)` 를 출력하세요. 발산하거나 진동하는 패턴을 눈으로 보는 것이 디버깅에 결정적입니다.

#### Step 4: ρ 적응 업데이트 (선택)

OSQP 논문의 휴리스틱:

$$
\rho \leftarrow \rho \sqrt{ \frac{\|r_p\|_\infty / \max(\|Ax\|_\infty, \|z\|_\infty)}{\|r_d\|_\infty / \max(\|Px\|_\infty, \|A^\top y\|_\infty, \|q\|_\infty)} }
$$

ρ 가 바뀌면 KKT 행렬도 바뀌므로 재분해가 필요합니다. 실제로 매 iteration 바꾸지 말고, 일정 간격 (예: 25 iter) 마다만 갱신하세요.

## 2. Ruiz Equilibration

### 2.1 개념

ADMM 같은 1차 방법은 행렬의 **조건수(condition number)** 에 매우 민감합니다. 컨디셔닝이 나쁜 행렬은 수렴 속도를 수십~수백 배 떨어뜨릴 수 있습니다.

**Ruiz equilibration** 은 행렬의 행과 열의 무한대 노름을 모두 1 근처로 만드는 대각 스케일링을 반복적으로 찾는 알고리즘입니다. 매우 단순한 휴리스틱인데도 OSQP 같은 실전 솔버에서 채택할 만큼 효과적입니다.

목표: 주어진 행렬 $M$ 에 대해 대각행렬 $D, E$ 를 찾아

$$
\hat M = D M E
$$

가 모든 행과 열의 $\infty$-norm 이 1 에 가깝도록.

### 2.2 알고리즘

QP 의 KKT 행렬은 대칭이므로 $D = E$ 인 단일 스케일링을 쓰면 충분합니다.

```
입력: M (대칭 행렬)
1. D = I 로 초기화
2. 반복 (예: 10회):
     d_i = 1 / sqrt(‖M[i, :]‖_∞)   # 각 행의 ∞-norm 의 역제곱근
     M ← diag(d) · M · diag(d)
     D ← D · diag(d)
3. return D, M_scaled
```

핵심은 "행/열 노름의 역제곱근" 을 곱하는 것이고, 이것을 몇 번 반복하면 빠르게 안정됩니다.

QP 전체에 적용할 때는 cost vector $q$ 와 constraint vector $l, u$ 도 함께 스케일링해야 합니다:

$$
\hat q = D q, \qquad \hat A = E A D, \qquad \hat l = E l, \qquad \hat u = E u
$$

여기서 $D$ 는 변수 스케일링, $E$ 는 제약 스케일링입니다.

### 2.3 Python 구현 가이드

`solvers/scaling.py` 에:

```python
def ruiz_equilibration(M, n_iter=10):
    """대칭 행렬 M 에 대해 D 를 찾아 D M D 의 행/열 노름을 1 근처로."""
    n = M.shape[0]
    D = np.ones(n)
    M_scaled = M.copy()
    for _ in range(n_iter):
        row_norms = np.maximum(np.linalg.norm(M_scaled, ord=np.inf, axis=1), 1e-10)
        d = 1.0 / np.sqrt(row_norms)
        M_scaled = (d[:, None] * M_scaled) * d[None, :]
        D *= d
    return D, M_scaled
```

QP 전체 스케일링 함수를 별도로:

```python

    # 자세한 식은 OSQP 논문 §5 참고
    ...
    return P_s, q_s, A_s, l_s, u_s, D, E
```

스케일링된 문제를 풀고 나면 원래 변수로 되돌려야 합니다: $x = D \hat x$, $y = E \hat y$.

## 3. SQP (Sequential Quadratic Programming)

### 3.1 개념

이제 비선형 최적화 (NLP) 로 넘어갑니다:

$$
\min_x f(x) \quad \text{s.t.} \quad g(x) \le 0, \; h(x) = 0
$$

**SQP 의 핵심 아이디어**: 현재 점 $x_k$ 근처에서 목적함수를 quadratic 으로, 제약을 linear 로 근사한 **QP subproblem** 을 풀어 step $\Delta x$ 를 얻고, $x_{k+1} = x_k + \alpha \Delta x$ 로 업데이트한다. 이걸 반복하면 KKT point 로 수렴.

각 iteration 의 QP subproblem:

$$
\min_{\Delta x} \; \tfrac{1}{2} \Delta x^\top H_k \Delta x + \nabla f(x_k)^\top \Delta x
$$

$$
\text{s.t.} \quad \nabla g(x_k)^\top \Delta x + g(x_k) \le 0
$$

$$
\quad\quad\quad \nabla h(x_k)^\top \Delta x + h(x_k) = 0
$$

여기서 $H_k$ 는 **Lagrangian 의 Hessian** 입니다 (목적함수 Hessian 이 아닙니다):

$$
\mathcal{L}(x, \lambda, \mu) = f(x) + \lambda^\top g(x) + \mu^\top h(x)
$$

$$
H_k = \nabla^2_{xx} \mathcal{L}(x_k, \lambda_k, \mu_k)
$$

이 점이 SQP 의 핵심이자 미묘한 부분입니다. **목적함수의 Hessian 만 쓰면 제약의 곡률 정보가 빠져서 수렴이 망가집니다.**

> **놀라운 부분**: SQP 의 부품으로 Phase 1 의 ADMM QP 솔버가 그대로 들어갑니다. 직접 만든 솔버를 다음 단계에서 부품으로 재사용하는 첫 순간이고, 이 경험이 본 학습 트랙의 핵심 보상입니다.

### 3.2 알고리즘 요약

```
입력: f, g, h, x_0
1. λ, μ 초기화 (보통 0)
2. 반복:
     (a) ∇f, ∇g, ∇h 계산 (CasADi 의 자동미분)
     (b) Lagrangian Hessian H_k 계산 (또는 BFGS 근사)
     (c) QP subproblem 풀이 → Δx, λ_new, μ_new   ← Phase 1 솔버 호출!
     (d) Merit function 으로 line search → α
     (e) x ← x + α Δx
     (f) λ, μ 업데이트
     (g) KKT residual < ε 이면 종료
```

### 3.3 핵심 이슈 1: 자동미분

수치미분 ($\nabla f \approx (f(x+h) - f(x))/h$) 직접 구현은 **추천하지 않습니다**. 학습 가치 대비 시간 낭비가 큽니다. CasADi 를 쓰면:

```python
import casadi as ca

x = ca.SX.sym('x', n)
f_expr = ...  # x 로 작성한 목적함수
g_expr = ...

f_fn = ca.Function('f', [x], [f_expr])
grad_f_fn = ca.Function('grad_f', [x], [ca.jacobian(f_expr, x).T])
hess_L_fn = ...  # Lagrangian Hessian 도 ca.hessian 으로
```

이렇게 만들어두면 numpy 함수처럼 호출할 수 있고, 정확한 도함수가 무료로 나옵니다.

### 3.4 핵심 이슈 2: Hessian 보정

$H_k$ 가 indefinite 일 수 있습니다 (Lagrangian Hessian 이 양정부호일 보장이 없음). 이러면 QP 가 unbounded 가 되거나 ADMM 솔버가 발산합니다. 두 가지 대응책:

**(a) BFGS 근사** (구현 쉬움, 추천)

$H$ 를 직접 계산하지 않고 step 마다 다음 식으로 업데이트:

$$
H_{k+1} = H_k - \frac{H_k s_k s_k^\top H_k}{s_k^\top H_k s_k} + \frac{y_k y_k^\top}{y_k^\top s_k}
$$

여기서 $s_k = x_{k+1} - x_k$, $y_k = \nabla \mathcal{L}_{k+1} - \nabla \mathcal{L}_k$. 항상 양정부호로 유지되는 게 장점.

Damped BFGS (Powell's modification) 를 쓰면 $y_k^\top s_k > 0$ 이 깨지는 경우도 안전합니다.

**(b) Modified Cholesky** (더 정확하지만 복잡)

실제 Lagrangian Hessian 을 계산하되, indefinite 면 대각에 $\tau I$ 를 더해서 양정부호로 만든다. 처음에는 BFGS 로 시작하길 권장.

### 3.5 핵심 이슈 3: Line Search 와 Merit Function

QP 가 준 step $\Delta x$ 를 그대로 쓰면 발산할 수 있습니다. 적절한 step size $\alpha \in (0, 1]$ 을 찾기 위해 **merit function** 을 정의합니다:

$$
\phi_\mu(x) = f(x) + \mu \|h(x)\|_1 + \mu \|\max(0, g(x))\|_1
$$

이 $\phi$ 가 충분히 감소하는 $\alpha$ 를 backtracking 으로 찾습니다 (Armijo condition):

$$
\phi(x_k + \alpha \Delta x) \le \phi(x_k) + c_1 \alpha D\phi(x_k; \Delta x)
$$

$\mu$ 는 라그랑지 듀얼 변수의 norm 보다 충분히 크게 (예: $\mu = 10 \|\lambda\|_\infty$).

### 3.6 Python 구현 가이드

`solvers/sqp.py` 의 클래스 골격:

```python
class SQPSolver:
    def __init__(self, problem, qp_solver, hessian_mode='bfgs',
                 max_iter=100, tol=1e-6):
        """
        problem: dict with keys 'f', 'g', 'h', 'x0' (CasADi 함수들)
        qp_solver: Phase 1 의 ADMMQPSolver (factory 형태로)
        """
        ...

    def solve(self):
        x = self.x0.copy()
        H = np.eye(self.n)  # BFGS 초기값
        for k in range(self.max_iter):
            # 1. derivatives
            grad_f = self.grad_f(x)
            J_g, J_h = self.J_g(x), self.J_h(x)
            g_val, h_val = self.g(x), self.h(x)

            # 2. QP subproblem 구성 후 풀이 (Phase 1 솔버 호출)
            delta_x, lam_new, mu_new = self._solve_qp(H, grad_f, J_g, g_val, J_h, h_val)

            # 3. line search
            alpha = self._line_search(x, delta_x, lam_new, mu_new)

            # 4. update
            x_new = x + alpha * delta_x

            # 5. BFGS update
            H = self._bfgs_update(H, x_new - x, ...)

            # 6. 수렴 체크
            if self._kkt_residual(x_new, lam_new, mu_new) < self.tol:
                return x_new
            x = x_new
```

### 3.7 검증 방법

1. **제약 없는 Rosenbrock**: $f(x_1, x_2) = (1-x_1)^2 + 100(x_2 - x_1^2)^2$. 답은 $(1, 1)$. scipy.optimize.minimize 와 같은 답이 나오면 통과.

2. **HS71** (유명한 NLP 테스트 문제):

   $$\min x_1 x_4 (x_1 + x_2 + x_3) + x_3$$
   $$\text{s.t.} \quad x_1 x_2 x_3 x_4 \ge 25, \quad \sum x_i^2 = 40, \quad 1 \le x_i \le 5$$

   답: $x^* \approx (1.0, 4.743, 3.821, 1.379)$, $f^* \approx 17.014$. IPOPT 답과 비교.

3. **Hock-Schittkowski 문제집**: 100+ 개의 표준 NLP 문제. 처음에는 5–10 개만 풀어봐도 충분.

### 3.8 자주 막히는 지점

| 증상 | 원인 | 해결 |
|------|------|------|
| QP subproblem 이 infeasible | 선형화된 제약이 동시에 만족 불가 | Slack 변수 도입 ($\ell_1$ penalty 형태) |
| Line search 가 $\alpha \to 0$ | merit function 의 $\mu$ 가 너무 작음 | $\mu$ 를 듀얼 norm 의 1.5–10배로 키움 |
| 수렴 후 KKT residual 큼 | derivative 계산 실수 | CasADi 의 결과를 finite difference 로 sanity check |
| BFGS Hessian 이 폭발 | $y_k^\top s_k \le 0$ 일 때 처리 안 함 | Damped BFGS 또는 skip |

### 3.9 완료 기준

> HS71 을 직접 만든 SQP 로 풀었을 때, IPOPT 답과 $\|x_{\text{mine}} - x_{\text{ipopt}}\|_\infty < 10^{-4}$ 이내로 일치한다.

## 4. Real-Time Iteration Scheme

### 4.1 개념

SQP 는 한 번 호출당 여러 iteration 을 돌려 정확한 NLP 해를 찾습니다. 그런데 NMPC 같은 **실시간 제어** 환경에서는 매 제어 주기마다 NLP 를 풀어야 합니다. 100 Hz 제어라면 한 번에 10 ms 안에 풀려야 한다는 뜻인데, full SQP 는 너무 느립니다.

**Real-Time Iteration (RTI) [Diehl 2005]** 의 통찰: NMPC 는 매 제어 주기마다 이전 해를 워밍업으로 쓸 수 있고, 시스템 상태도 조금씩만 변하므로, **매 호출에서 SQP iteration 을 단 1회만 돌려도 closed-loop 안정성이 유지된다.**

쉽게 말해: "수렴 안 된 답이라도 매 주기마다 빠르게 한 번씩 개선하면, 결국 추적이 따라잡는다." 라는 발상입니다. **optimality 를 responsiveness 와 거래** 하는 것이고, 이 거래가 실용적으로 매우 잘 작동합니다.

### 4.2 알고리즘

기본적으로 SQP 와 동일한데, **외부 루프를 1회로 고정**합니다:

```
NMPC 메인 루프 (매 제어 주기마다):
  1. 현재 측정값으로 x_0 갱신
  2. 이전 주기의 해 z_prev 를 워밍업으로 사용
  3. SQP iteration 1회만 수행:
       - linearize, QP 풀이, line search, 업데이트
  4. 첫 제어입력 u_0 만 시스템에 적용
  5. 다음 주기 대기
```

추가로 자주 쓰이는 두 가지 트릭:

**(a) Preparation–Feedback split**

한 주기 안의 계산을 두 단계로 나눕니다:

- **Preparation phase** (이전 주기 끝나자마자): linearization, KKT 행렬 구성, 분해. 새 측정값 없이 가능한 모든 작업.
- **Feedback phase** (새 측정값 도착 직후): 측정값으로 RHS 만 갱신해서 backsolve. 매우 빠름.

이 분리로 "제어 latency" 를 millisecond 단위로 줄일 수 있습니다. 자율주행이나 로봇에서 실제로 쓰는 기법.

**(b) Shifting**

이전 horizon 의 해를 한 칸 앞으로 미루어 새 horizon 의 초기 추측으로 씁니다:

$$
z^{\text{init}}_i = z^{\text{prev}}_{i+1}, \quad i = 0, \ldots, T-2
$$

마지막 노드는 적당히 외삽 (보통 stage cost 를 minimize 하는 steady state).

### 4.3 Python 구현 가이드

Phase 3 에서 만든 SQP 솔버에 모드 옵션을 추가하면 됩니다:

```python
class SQPSolver:
    def __init__(self, ..., mode='full'):  # 'full' or 'rti'
        self.mode = mode
        # RTI 모드면 상태를 인스턴스에 저장
        self._z_prev = None
        self._H_prev = None

    def solve_rti(self, x0):
        """한 번 호출당 SQP iteration 1회."""
        if self._z_prev is None:
            self._z_prev = self._initial_guess(x0)
            self._H_prev = np.eye(self.n)

        z = self._shift(self._z_prev)  # 이전 해 한 칸 미루기
        # SQP 1 iteration
        delta_z, lam, mu = self._sqp_step(z, self._H_prev)
        z_new = z + delta_z

        # BFGS 업데이트
        self._H_prev = self._bfgs_update(self._H_prev, ...)
        self._z_prev = z_new
        return z_new
```

### 4.4 실험 설계

RTI 의 효과를 체감하려면 **closed-loop 실험** 이 필수입니다. 4차원 정도의 비선형 시스템 추적이 적당합니다:

**예: Van der Pol oscillator 추적**

$$
\dot x_1 = x_2, \qquad \dot x_2 = \mu(1-x_1^2) x_2 - x_1 + u
$$

$x_1$ 이 사인 곡선을 추적하도록 $u$ 를 NMPC 로 결정. 이 예제는 동역학이 단순하지만 비선형이라 NMPC 검증용으로 자주 쓰입니다.

**비교 항목**:

| 모드 | 한 주기 풀이 시간 | 추적 오차 RMS | 비고 |
|------|------------------|--------------|------|
| Full SQP (10 iter) | ~50 ms | 매우 작음 | 실시간 안 됨 |
| RTI (1 iter) | ~3 ms | 약간 큼 | 100 Hz 가능 |
| RTI + prep/feedback | ~0.5 ms feedback | RTI 와 비슷 | latency 최소 |

이런 표를 직접 측정해서 채우면, RTI 의 의미가 손에 잡힙니다.

### 4.5 검증 방법

1. **수렴성 확인**: RTI 를 정상상태에서 무한히 돌리면 full SQP 답으로 수렴하는지. 시스템을 안정점에서 disturb 시키고 RTI 만 돌렸을 때 full SQP 의 해와의 거리가 0 으로 가는지 plot.

2. **추적 비교**: 같은 추적 task 를 full SQP 와 RTI 로 각각 closed-loop 시뮬레이션. 추적 오차와 계산시간 비교 그래프.

3. **외란 강건성**: 외란 주입 후 회복 속도 비교.

### 4.6 자주 막히는 지점

| 증상 | 원인 | 해결 |
|------|------|------|
| RTI 발산 | 워밍업이 너무 나쁨 | 첫 몇 주기는 full SQP 로 시작 |
| 추적 오차 누적 | shifting 이 부정확 | 마지막 노드 외삽 식 점검 |
| Preparation phase 가 느림 | linearization 을 매번 새로 함 | CasADi 함수 JIT 컴파일 |

### 4.7 완료 기준

> Van der Pol 또는 cart-pole 추적 문제에서 RTI 를 100 Hz closed-loop 로 돌렸을 때, full SQP 와 비슷한 추적 성능을 보이면서 한 주기 계산 시간이 10 ms 이하다.

## 전체 진행 순서와 시간 예산

### 추천 학습 순서

```
Phase 1: ADMM QP 솔버 (1–2주)
   ↓
Phase 2: Ruiz Equilibration (3–5일)   ← Phase 1 솔버에 plug-in
   ↓
Phase 3: SQP (2–3주)                   ← Phase 1 솔버를 부품으로 사용
   ↓
Phase 4: RTI Scheme (1–1.5주)          ← Phase 3 솔버에 모드 추가
```

각 phase 가 다음 phase 의 부품이 되는 누적 구조입니다. Phase 1 만 견고히 만들어두면 그 후는 비교적 빠르게 진행됩니다.

### 평일 저녁 1–2시간 + 주말 기준 일정

| Phase | 기간 | 마일스톤 |
|-------|------|---------|
| Phase 1 | 2주 | 임의 QP 100개 cvxpy 비교 통과 |
| Phase 2 | 0.5주 | Ruiz 적용 시 수렴 5배 가속 확인 |
| Phase 3 | 3주 | HS71 IPOPT 답과 일치 |
| Phase 4 | 1.5주 | Van der Pol 100 Hz 추적 성공 |
| **합계** | **약 7주** | NMPC 풀스택 보유 |

풀타임이면 3–4주, 천천히 가도 두 달 안쪽입니다.

### 가장 큰 걸림돌과 우선순위

1. **꼭 챙길 것**: 각 phase 끝마다 cvxpy/scipy/IPOPT 와의 정량적 비교. 이게 빠지면 미묘한 버그가 누적되어 Phase 4 에서 폭발합니다.
2. **건너뛰어도 되는 것**: Modified Cholesky, infeasibility detection, sparse matrix 최적화. 처음 학습에서는 dense + BFGS 면 충분합니다.
3. **시간 잡아먹는 함정**: 수치미분 직접 구현, 자기만의 자동미분 만들기. CasADi 쓰세요.

- ADMM, KKT 시스템, LDL 분해, line search, BFGS 의 **수식 차원이 아닌 코드 차원의 이해**
