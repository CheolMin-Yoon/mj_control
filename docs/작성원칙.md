# 작성원칙

`source/`·`scripts/`의 명명·주석·구조 계약. 근거는 skills [공유 계약](/home/frlab/skills/docs/shared-contract.md)(§)과
[casadi_skills](https://github.com/CheolMin-Yoon/casadi_skills)이고, 다른 점은 항목 옆에 이유를 적는다.

## 1. 배치

| 위치 | 소유 |
| --- | --- |
| `source/sim/` | MuJoCo 실행: `MujocoKernel`, `SimScheduler`, `Visualizer`, `DataLogger`, plot |
| `source/dynamics/` | 모델 함수: `PinocchioWrapper`, `MujocoWrapper`, `CartpoleDynamics`, 이산화 |
| `source/control/` | 제어기·궤적: `TaskSpaceController`, `TrajectoryGenerator`, `EETracking`, `lqr_gain` |
| `source/solvers/` | 수치 solver: `OSQPSolver` |
| `source/robots/<robot>/` | `constants.py`(경로·관절·frame·actuator 사실), `xmls/`(MJCF·URDF·mesh, 장면 `scene*.xml`) |
| `scripts/` | viewer 실행 진입점, 로봇별 조립과 주기 상수(`CTRL_HZ`) |

로봇이 아니라 역할로 나눈다(casadi_skills `dynamics/`·`control/`·`solvers/`·`robots/`). 로봇 고유 사실은 `robots/<robot>/constants.py`의
`<ROBOT>_*` 상수(§4.1.6, casadi `robots/g1/constants.py`)이고, 그 밖의 module-level 상수는 두지 않는다(§4.1.5).

## 2. 이름 순서와 접미사

1. 순서는 대상·물리량·역할·frame: `ee_pos_des_w`, `ee_lin_vel_w`, `joint_pos_des` (§5.1.1)
2. Frame 축은 `_w`(world, Pinocchio `LOCAL_WORLD_ALIGNED` 포함)와 `_b`(그 frame 자신의 body 축, Pinocchio `LOCAL`) 두 가지다.
   대상이 이름에 있으면 그 대상의 body 축이다(`base_*_b`, `ee_*_b`)
3. 서로 다른 frame이 섞인 묶음은 접미사 없이 docstring에 부분별 frame을 적는다

| 대상 | 이름 | 근거 |
| --- | --- | --- |
| 목표·오차·시계열 참조 | `_des`·`_err`·`_ref` | 기존 관례, 식에 맞게 짧게 |
| 개수 | `num_*` | §2.1 |
| index | `*_id`·`*_ids` | §5.3.2, casadi `frame_ids` |
| 하한·상한 | `*_lower`·`*_upper`, `max_*` | casadi `joint_position_lower`, §2.1 |
| 정규화 | `*_regularization` | casadi `hessian_regularization` |
| 사전 할당 버퍼 | `_*_buf` | 기존 |

4. 물리량 약칭은 `pos`, `mat`(3×3 회전, MuJoCo `xmat`), `quat`, `pose`(`pin.SE3`·`FramePose`), `lin_vel`, `ang_vel`, `twist`,
   `wrench`, `acc`. 6D 벡터는 `[linear; angular]`(Pinocchio `Motion`)
5. Link 원점과 질량중심은 `link`·`com`으로 구분한다(§5.1.5)
6. 차원 `nq`·`nv`와 stock 속성(`data.oMf`, `qpos`, `qvel`, `lowerPositionLimit`)은 stock 이름 그대로다(§2.3.4)

## 3. 동역학 항

| 양 | 이름 |
| --- | --- |
| M⁻¹ | `mass_matrix_inv` |
| C·q̇ + g | `bias_forces` |
| frame Jacobian | `jacobian_w(key)` |
| frame 자세, 자세 + 속도 | `frame_pose_w(key)`, `frame_state_w(key)` |
| M, g, C, J̇q̇가 필요해지면 | `mass_matrix`, `generalized_gravity`, `coriolis_matrix`, `jdot_velocity_w(key)` (casadi `whole_body_terms.py`) |

`PinocchioWrapper`와 `MujocoWrapper`는 같은 interface이고 frame key(`"ee"`, 양팔은 `"left_hand"`·`"right_hand"`)는 역할 이름,
model frame 이름은 `constants.py`가 소유한다. Frame·관절 순서는 기본값으로 숨기지 않고 생성자 필수 인자다(§4.2.2).

## 4. 수식 기호

1. 함수 본문의 식 기호 허용: `M`, `J`, `Lambda`, `H`, `A_d` (§2.3.8)
2. 수학 함수 인자의 표준 기호 허용: LTI `A`·`B`, LQR `Q`·`R`
3. `q`·`dq`·`ddq`·`tau`는 기호 유지(casadi HQP `[ddq, beta, tau]`)
4. Module을 넘는 속성·method·인자는 단어 이름이다(§2.3.8 "물리·task 경계 이름은 frame, unit, 역할")
5. Ruff는 N801·N802를 강제하고 식 기호 때문에 N803·N806만 제외한다(`pyproject.toml`)

## 5. Class·함수

1. Class는 밑줄 없는 CapWords, 약어 대문자 유지(`OSQPSolver`, `EETracking`, ruff N801)
2. 함수·method는 반환 역할 이름(`impedance_torque`, `tracking_error`, `lqr_gain`). `compute_`는 역할만으로 불분명할 때만(§3)
3. 동사: `update_*` 매 step in-place, `apply_*` 시뮬레이터에 명령 쓰기, `reset_*`, `solve`, `draw_*` viewer, `plot_*` matplotlib
4. 내부 helper는 `_` prefix(§4.1.4)
5. Wrapper class는 state·lifecycle 책임이 있을 때만 둔다(§4.4.1). 상태 없는 계산은 함수다(`lqr_gain`, `zoh`)

## 6. Public API

1. Package public은 `__init__.py`의 `__all__` re-export뿐이다(§4.1.1)
2. `scripts/`는 re-export 경로(`source.sim`, `source.control`), package 안은 owning module을 import한다(§4.1.2)

## 7. 자세·quaternion 경계

1. Runtime 자세는 회전행렬 `*_mat_w`. 회전 오차 `log3(mat_des_w @ mat_w.T)`는 world 축
2. Quaternion은 MuJoCo WXYZ(§5.2.1), Pinocchio free-flyer q는 XYZW. 변환은 MuJoCo↔Pinocchio 경계 한 곳에서만 한다
3. 고정 기반 모델은 q에 quaternion이 없어 관절 순서 매핑(`MujocoKernel.qpos_ids`·`dof_ids`)만 필요하다

## 8. 주석·docstring

1. 마침표 없는 짧은 한국어 명사형(`~함`, `~반환`, 원인→결과 화살표), 영어 용어는 그대로
2. 절 제목은 `인자:`·`반환:`, 항목은 한 줄(§7.1)
3. Shape·frame·단위·tuple 순서·부수효과만 적고 이름으로 드러나는 인자는 생략(§7.3–4)
4. Config 검사 위에는 이유 주석을 달지 않는다
5. 수식을 구현한 함수는 식이 짧아도 raw docstring `r"""`에 `$$ … $$` LaTeX 블록만 두고 설명 문장은 쓰지 않는다. 논문 식
   번호는 `\tag{26}`, 특수 경우(ξ = 0 등)도 수식으로 적는다

## 9. 검사와 lint

1. Runtime 검사는 stock도 하는 검사만 둔다(§8.1–2). 이름 오탈자는 MuJoCo·Pinocchio가 내는 예외에 맡긴다
2. 형식은 `ruff format`, lint는 `ruff check`(line-length 120, `E,W,F,I,N,B,UP`)
