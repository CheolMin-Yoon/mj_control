#### 작성원칙

이 문서는 `mj_sim/` 전체의 명명·구조 컨벤션입니다. Pinocchio + MuJoCo Python 환경 기준.

핵심 한 줄: **단일문자(수식·내부)는 짧게, 단어(공개 API)는 명확하게, 좌표계는 `_W`/`_B`로 명시.**

---

##### 메서드 prefix

1. **`compute_*`** — 호출 시점에 수치 연산을 새로 수행. 입력 → 출력.
   *Why*: 호출 비용이 있다는 신호. 루프에서 함부로 부르지 말라는 호출자 알림.
   *예*: `compute_J_W(key)`, `compute_ee_state_W(key)`, `compute_DLS(...)`, `compute_rpy_world()`.
   *비고*: 모든 수치 빌더는 `compute_*` (Pinocchio `computeAllTerms`와 일치).

2. **`update_*`** — 매 step in-place 갱신. 반환 없음 또는 self.
   *예*: `update_model(q, dq)`, `update_robot_state(state)`, `update_continuous_dynamics()`.

3. **`solve_*`** — QP/LP/MPC 솔버 호출.
   *예*: `solve_dense_mpc()`, `solve_lqr()`, `solve_DARE()`.

4. **`get_*`** — 캐시된 단순 조회. `compute_*`보다 가벼움. 인자 받아서 키로 꺼낼 때만.
   *예*: `get_hip_offset(leg)`, `get_foot_contact_state()`.
   ⚠️ `set_*` 짝으로 만들지 말 것. setter는 `@property setter` 또는 직접 속성 할당.

5. **`@property`** — 인자 없는 단일 값. **싼 access + side-effect free**.
   *Why*: 호출자가 변수처럼 쓰므로 비싸거나 부작용 있으면 절대 안 됨.
   비싼 건 `compute_*`로, 부작용 있는 건 동사형 메서드로.
   *예*: `wrapper.M`, `wrapper.M_inv`, `wrapper.J_com`, `wrapper.p_com_W`.

6. **부작용 있는 동작은 동사형 메서드** — prefix 없이 동사 그대로.
   *예*: `step`, `register_foot_geoms`, `reset_yaw_unwrap`.

7. **시각화/플롯 prefix**:
   - matplotlib 함수 → `plot_*` (`plot_helpers.py`)
   - MuJoCo viewer 오버레이 → `draw_*` (`Visualizer` 메서드)

##### 변수 명명

8. **단일문자는 수식·내부 변수·클래스 멤버에**:
   - `m` (mass), `M` (mass matrix), `J` (Jacobian), `R` (rotation), `I_body`/`I_world` (inertia)
   - `q`, `dq`, `tau`, `p`, `v`, `a`, `F`
   *Why*: 수학 식과 코드의 거리 줄임. `mass`처럼 풀어쓰면 `m * g` 같은 식이 길어짐.

9. **공개 API·로그 키는 단어로**:
   - `target_pos`, `actual_pos`, `feet_jacobians`, `joint_names`
   *Why*: 외부 노출 인터페이스는 가독성 우선. 단일문자는 호출자에게 의미 모호함.

10. **suffix는 `_des` / `_err`만, 현재값은 plain**:
    - desired: `pos_des`, `tau_des`, `f_grf_des`
    - error: `pose_err`, `pos_err` (즉석 차감 가능하면 변수로 안 만들어도 됨)
    - current/measured: **suffix 없음** (`pos`, `q`, `tau`)
    - reference trajectory: `_ref` (시계열, 시간 인덱스 있음. `_des`와 구분)
    - terminal goal: `_target` (mission goal, MPC terminal cost용)
    *Why*: 같은 물리량(`pos_*`)이 grep·정렬·자동완성 시 묶임. `_curr` 사용 X (잡음).

11. **좌표계 suffix `_W` / `_B` / `_H`** (단일 대문자):
    - `_W` = world, `_B` = body, `_H` = hip/horizontal
    - 회전: `R_WB` (B→W, "from B to W as expressed in W"), `R_BW` (그 transpose)
    - 위치: `p_com_W`, `p_base_W`, `r_feet` (3×4 W frame)
    - 속도: `v_com_W`, `omega_base_B`
    *Why*: `_world`/`_body` 풀어쓰기는 길어서 식이 늘어짐. 단일 대문자가 수식과 잘 어울림.

12. **물리량 prefix는 단일문자 + `_`**:
    - `p_` (pos), `v_` (vel), `a_` (acc), `q_`/`dq_` (joint), `tau_`, `F_`, `J_`, `R_`, `M_`
    *예*: `p_com_W`, `v_com_W`, `R_WB`, `J_com`, `tau_des`.

13. **SRBD/MPC 변수**:
    - 13D 상태: `x_0` (초기), `x` (symbolic), `x_ref` (참조)
    - 행렬: `Ac`/`Bc` (continuous), `Ad`/`Bd` (discrete), `A_qp`/`B_qp` (horizon stack)
    - 이산화 함수: `c2d` (LTI 단일 시스템), `c2qp` (MPC horizon stack 포함)
    - GRF 입력: `u_grf` (12D = 4발×3) 또는 `f_grf`
    - 발 위치 행렬: `r_feet` (3×4, columns `[FL, FR, RL, RR]`)
    - 관성: `I_body` (body frame, 시간 불변), `I_world` (centroidal world, `R_yaw @ I_body @ R_yaw.T`)

14. **발 인덱싱**: 문자열 키 `"FL"`, `"FR"`, `"RL"`, `"RR"`.
    표준 순서 `LEG_KEYS = ("FL", "FR", "RL", "RR")` 모듈 상수로 정의.
    `LEG_IDX = {k: i for i, k in enumerate(LEG_KEYS)}`로 정수 매핑.
    `r_feet[:, LEG_IDX["FL"]]` 식으로 접근.

##### Underscore prefix 규칙

15. **`_xxx` (single underscore)** — private 멤버/메서드. **leading underscore 일관 적용**.
    - `self._q`, `self._dq` — Pinocchio API에 직접 넘기는 raw 입력. 외부에 `@property q`로 노출.
    - `self._M_inv` — `update_model`에서 캐시한 결과. 외부에 `@property M_inv`로.
    - `self._yaw_cont`, `self._yaw_unwrap_init` — 내부 상태머신.
    - `def _build_constraints(self)`, `def _scipy_to_casadi(...)` — 헬퍼 메서드.
    *Why*: Python 표준 컨벤션. 호출자에게 "외부 사용 비추천" 신호.

16. **`_buf` suffix** — pre-allocated numpy 버퍼. 외부 노출 X, in-place 갱신.
    *예*: `self._q_buf`, `self._dq_buf`, `self._force_buf`, `self._r_feet`.
    *Why*: 매 step 새 배열 할당 회피. Real-time 제어 루프 표준 패턴.
    `update_*` 안에서 `np.copyto(self._buf, ...)` 또는 `self._buf[:] = ...`로 채움.

17. **`__xxx` (double underscore)** — 사용 금지.
    *Why*: name mangling. 상속 깨짐. 진짜 비공개가 필요할 일은 거의 없음.
    `__init__`, `__repr__` 같은 dunder 매직 메서드만 예외.

##### 모듈 상수 / 전역

18. **모듈 상수는 `UPPER_SNAKE_CASE`. import 직후 상단**, 클래스 위.
    *예*: `G1_FRAMES`, `LEG_KEYS`, `LEG_IDX`, `FOOT_SOLE_OFFSET`, `MANIPULATOR_FRAMES`.

19. **`_` prefix 모듈 상수** — 모듈 내부 전용 (외부 import 금지 의도).
    *예*: `_ANKLE_LINKS` (humanoid wrapper에서 virtual frame 등록용 내부 dict).

##### 주석

20. **카테고리 헤더는 한국어, 번호 X**. 위·아래 빈 줄 1개로 경계.

    ```python
    # 상태

    @property
    def q(self):  ...
    @property
    def dq(self): ...

    # 동역학

    @property
    def M(self):     ...
    @property
    def M_inv(self): ...
    ```

21. **인라인 주석은 "왜"만**. 코드가 이미 말하는 "무엇"은 쓰지 않음.
    *예외*: 비표준 변환, 매직넘버, 외부 컨벤션 차이 (MJ `(w,x,y,z)` vs Pin `(x,y,z,w)` 등).

22. **Docstring은 1줄 또는 생략**. 시그니처+이름이 자명하면 안 씀. 단위·shape·side effect가 모호한 경우만:

    ```python
    def compute_DLS(self, twist_des, twist_err, J):
        """V_des = twist_des + Kp·err → dq_des (na,)"""
    ```

##### 파일 / 클래스 구조

23. **클래스 내부 멤버 순서**:
    1. `__init__`
    2. 핵심 update/step (있다면) — `update_model`, `update_robot_state`, `step`
    3. `@property` (카테고리별 묶음, 빈 줄 1로 분리)
    4. 메서드 (`compute_*` → `solve_*` → `get_*` → 변환 → 유틸 순)
    5. private 헬퍼 (`_build_*`, `_compute_*`)

    *Why*: 위에서 아래로 "초기화 → 매 step 동작 → 노출 상태 → 보조 연산 → 내부 헬퍼"의 자연스러운 흐름.

24. **import → 모듈 상수 → 클래스** 순서.
    상수는 import 직후, 클래스 정의 위.

---

##### 클래스 vs 함수

25. **상태가 있으면 클래스, 없으면 함수**.
    - 클래스: 파라미터·캐시·내부 행렬을 한 번 구성해두고 여러 번 호출 (`Pinocchio_Wrapper`, `LQR(A, B, Q, R)`).
    - 함수: 입력 → 출력. 부작용 없음 (`rk4`, `zoh`, `taylor2`, `c2d`).
    *Why*: 빈 `__init__` + 메서드만 있는 클래스는 함수의 위장. `Foo().bar(...)`보다 `bar(...)`가 호출자에게 더 정직.

26. **재사용 범위가 넓으면 모듈로 빼기**. 특정 로봇 전용이면 그 로봇 폴더 안에.
    *예*: `discretization.py` (모든 시스템 공용) vs `cartpole/cartpole_utils.py` (카트폴 전용).
    *판단 기준*: "다른 로봇에서도 import 해서 쓸 일이 있나?" → Yes면 공용, No면 로컬.

27. **MPC/SRBD는 책임별 클래스 분리**.
    한 거대 `MPC` 클래스 X. `SRBDDynamics`, `SRBDCost`, `SRBDConstraint`, `SRBDSolver` 분리.
    *Why*: cost·constraint·dynamics는 독립적으로 변하고, 각각 단위 테스트 가능.
